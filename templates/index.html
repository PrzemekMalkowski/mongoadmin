  • _mergeAuthzCollections is an internal command. userAdminAnyDatabase is not enough — your session needs the built-in restore role (or __system) on each target's admin database.
  • The source must let you read credentials (showCredentials: true works under userAdmin's viewUser action).
  • This bypasses createUser's validation pipeline — including any password-policy modules in MongoDB Enterprise / Percona PSMP.
  • SCRAM mechanism mismatch (e.g. source has SCRAM-SHA-1-only, target rejects SHA-1) will produce a user that cannot authenticate. Verify authenticationMechanisms is consistent across shards.
  • The currently common K8s operator pattern (MongoDB Community Operator, Percona PSMDB Operator) does not use this path — they store the plaintext in a Secret and call createUser like plaintext mode here. Prefer plaintext mode unless you specifically need byte-identical credentials.
MongoDB never exposes the source user's password hash, so you need to supply one. The created users on each target shard will get this password — the existing source account is unchanged.
